# Isolated hosted qualification preparation

The public homepage stays on its existing hosting. The private application builds into `private-app/dist` only. `hosting/firebase.json` names a separate target, `justelle-private-qualification`; there is no project binding, deploy credential, automatic deployment or change to `CNAME`. The preferred eventual hostname is `app.justelle.life`; a separately approved Firebase `*.web.app` qualification origin can be used first. Firebase documents [hosting targets](https://firebase.google.com/docs/hosting/multisites) and [custom subdomains](https://firebase.google.com/docs/hosting/custom-domain).

`npm run build` produces the isolated assets. With no configuration, the application still refuses non-local operation. A **fictional hosted trial** needs explicit build variables: `VITE_JUSTELLE_MODE=hosted-fictional`, `VITE_JUSTELLE_ORIGIN`, `VITE_FIREBASE_PROJECT_ID`, `VITE_FIREBASE_API_KEY`, `VITE_FIREBASE_AUTH_DOMAIN`, `VITE_FIREBASE_STORAGE_BUCKET`, `VITE_JUSTELLE_ROOM=fictional-room`. These are client configuration, not server credentials. The hostname and project must match; real-member mode is deliberately absent.

Hosted media uses `/api/media/<canonical-id>/original|preview`, with an identity token on every request and no-store responses. `media-handler.mjs` checks revocation and current room membership, uses immutable GCS writes, and refuses objects containing reusable Firebase download tokens. Hosted Storage Rules deny all direct client access. The local emulator retains its tested SDK route. This addresses a different boundary from simply avoiding `getDownloadURL`: real token behaviour, bucket IAM and the gateway must be tested together.

**Not deployable yet:** The HTTP handler is a tested dependency-injected core, not a registered Firebase Function or Cloud Run service. HTTPS routing, Admin identity verification with revocation checks, least-privilege service account, private bucket IAM, CORS/origin policy, runtime resource limits and protected mock-AI routing need an authorised hosted project. There are no `/api` rewrites in the hosting config, so it cannot silently publish a half-wired gateway. Do not deploy this config as a working application.

Once an approved fictional trial exists, `npm run qualify:hosted -- /outside-repository/trial.qualification.json` performs read-only checks. The external file supplies origin/project/room/bucket, one existing fictional record/image ID, and fictional member/outsider/revoked-member ID tokens. It verifies member access, denial for unauthenticated/outsider/revoked access, denial through Firebase’s direct endpoint, and denial through the raw GCS endpoint. It does not create accounts, change membership, activate billing or write data. Prepare revoked membership before the run. It prints statuses only, never tokens.

Also qualify: upload rejection/immutable retry, absence of metadata download tokens, public-token URL denial, persistent sessions on two actual iPhones (Safari and installed Home Screen), JPEG/PNG/real HEIC cases, loss-of-network recovery, sign-out and reopening, full encrypted backup recovery from the independent destination. HTTP/emulator tests cannot establish these results.

Before activation the owner must choose/approve the Firebase project and billing, final login provider, independent backup destination/key custody and AI budget. No service, DNS, account or billing was activated by this change.
